## Important implementation distinctions

- The generic action dispatcher and aggregate business-state document have been replaced by real typed collections and explicit feature routes. Shared transaction, policy and repository primitives live in `core/`; feature services own business behavior. Some simple controller/validation declarations are colocated with their route registrations rather than creating empty pass-through files.
- `/api/v1` paths follow the API catalogue. The web uses short hash routes shown above and shared tabs/dialogs instead of copying every `/app/:portal/...` example URL literally. Feature behavior and permissions, rather than the number of JSX files, are the intended coverage.
- Paid funding and outgoing transfers use operator reconciliation. Email uses a configured real webhook worker; no automatic delivery is claimed without configuration. Social metrics are self-reported and labelled.
- This is a clean-source rebuild. Existing prototype financial history/approval flags are not migrated automatically.
- Neither table membership nor route registration proves that an acceptance journey passed. See `VERIFICATION.md` for executed evidence and remaining checks.

## UI, reporting and realtime additions

See `UI_AUDIT.md` for screen mapping. New APIs: `GET /analytics/overview`, `GET /me/review-opportunities`, `GET /campaigns/:campaignId/reviews`, `GET /review-summaries/:targetId`. Campaign draft DTOs now accept `coverAssetId`; upload purpose includes `CAMPAIGN_COVER`; verified review DTOs accept optional `campaignStars`/`campaignFeedback`. Socket.IO events are `conversation:join`, `conversation:leave`, `message:send`, `conversation:read` and `conversation:typing`; server notifications include `message:new` and `conversation:revoked`. All socket handlers recheck normal persisted access policy.

Latest operations additions: `AdminOverview.jsx`, the shared Collection/Table controls, `ChatInbox.jsx`, `NotificationBell.jsx` and `core/list-presentation.js`. The additional API is `GET /inbox/summary`; `GET /conversations` now supports recent-activity pagination, unread/context filters and counterpart/campaign/latest-preview search. The `inbox:watch` event and authorized `inbox:changed` hints refresh unread badges outside the chat screen. General table search/sort applies to the loaded page and is labelled accordingly.
